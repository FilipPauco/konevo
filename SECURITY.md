# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected security vulnerability.

Email [filip.pauco08@gmail.com](mailto:filip.pauco08@gmail.com) with:

- a description of the vulnerability and its impact;
- safe, reproducible steps or a proof of concept;
- the affected version or commit; and
- suggested mitigation, if available.

Do not access, change, or retain data that does not belong to you. A receipt will
be acknowledged as availability permits. There is currently no response-time or
remediation-time guarantee.

## Supported versions

Until the first stable release, only the latest commit on the default branch is
considered for security fixes.

## Self-hosted security

Operators are responsible for their own deployment, secrets, database, backups,
and connected third-party accounts. Read the [security and operational hardening
guide](docs/SECURITY.md) before deploying Konevo with real data.
